# 存储与并发写入

## 批量文章状态

`FreshRSS_EntryDAO::markRead()` 的数组参数和 `markFavorite()` 使用事务执行整批操作。批量 ID 去重后按数据库参数上限分段，每段为状态、更新时间等参数预留位置。任意一段失败会返回 `false`，此前各段的文章状态和未读计数一起回滚；成功返回受影响的记录数。

SQLite 的单条已读操作也使用同一路径。若调用方已开启事务，DAO 使用保存点，成功不会提交调用方的事务，失败不会清除保存点之前的写入。异常同样会触发回滚，然后继续向调用方传播。插件状态钩子在本次 DAO 操作成功后触发；如果存在外层事务，其最终提交仍由调用方负责。

已读操作只重算本批涉及订阅源的未读计数，不扫描账户内其他订阅源。空数组直接返回 `0`，不会构造无效的 `IN ()` 查询。

`existingIds(array $ids): ?array` 分段查询现存文章 ID，不加载标题或正文。结果为去重的数字字符串数组；空输入返回空数组，数据库错误返回 `null`。结果顺序不构成接口约定。

`listByIds()` 在跨 SQL 参数上限分段读取时，先按完整 ID 列表排序并去重，保证各段合并后的整体升降序。比较直接使用十进制字符串，不把微秒级文章 ID 转成浮点数；回归测试覆盖超过 `2^53` 的相邻 ID。

## 新文章提交

三个数据库后端的 `commitNewEntries()` 通过共同的事务封装提交暂存文章。SQL 执行失败时回滚本次操作，避免提交已完成的部分语句；外层事务使用保存点隔离。SQLite 和 PostgreSQL 17.11 已使用真实安装 schema 执行暂存提交、失败回滚、保存点及重试合同，详见[数据库合同、并发与索引](database.md)。MySQL 的修改通过静态检查，尚未执行数据库实例集成测试。

## 日志轮转

日志写入在同一个文件锁中完成大小检查、轮转和追加，避免多个采集进程根据锁外的旧文件大小重复轮转。大小检查使用已打开文件的 `fstat()`，长驻进程不依赖 PHP 文件路径的状态缓存。

超过 `MAX_LOG_SIZE` 时，最多保留旧日志末尾约一半的字节，舍弃开头不完整的记录，再追加轮转记录和新日志。写入失败会报告权限异常，锁和文件句柄在异常路径也会释放。`MAX_LOG_SIZE` 是触发轮转的阈值，并非单条日志的硬大小限制；一次特别长的日志仍可能超过阈值，后续写入时再轮转。

## 调度进程集成测试

以下命令启动仅监听 `127.0.0.1` 的 HTTP 测试服务，创建独立临时数据目录和 SQLite 用户库，并调用真实的调度器及子进程。测试不会读取或修改现有用户数据。

```sh
python3 tests/integration/refresh/scheduler_test.py --php /path/to/php
```

需要 Python 3、提供 `/proc` 和进程组的 Linux 环境，以及具有 PDO SQLite、PCNTL 和 RSS 解析所需扩展的 PHP。测试覆盖成功抓取入库、慢响应超时终止、HTTP 500 重试、未到期任务不提前运行、失败恢复后入库和任务确认，以及退出后没有遗留工作进程。另覆盖父进程被强制终止后，工作进程由独立看门狗终止、释放锁，以及租约过期后的恢复。临时目录和测试服务在结束时清理。

## 并发修改配置

`Minz_Configuration::save()` 使用独立的临时文件和固定锁文件，检查完整写入、备份及最终替换是否成功。主配置以原子替换发布，配置和备份保持原文件权限。旧的完整快照 `save()` 仍采用最后写入者生效的语义。

新代码可使用以下接口，避免覆盖其他请求对不同字段的修改：

```php
// 只改指定顶层字段；null 删除持久化覆盖值，有默认值的字段恢复默认值。
$conf->savePatch(['language' => 'fr']);

// 修改嵌套配置：持锁重读最新值，再一次性发布。
$conf->mutate(static function (array $latest): array {
	$latest['reader_preferences']['density'] = 'compact';
	return $latest;
});

// 对需要确认旧状态的编辑，提交读取时取得的版本。
$version = $conf->version();
$conf->savePatch(['language' => 'en'], $version);
```

`version()` 使用安装时的系统 salt 生成 HMAC，并绑定配置文件身份；需要非空系统 salt，不公开裸配置内容摘要。版本不匹配时抛出 `Minz_ConfigurationConflictException`，文件写入失败返回 `false`。回调异常原样传播，不发布文件，也不修改对象原有状态。回调应只修改传入数组，不得调用配置保存方法；递归写入同一文件会立即失败，避免等待自己的锁。

测试覆盖最终替换失败、备份失败、权限保持、并发保存期间读取完整文件、旧对象修改不同字段、旧版本冲突、删除覆盖值后版本稳定，以及四个 PHP 进程同时递增配置值共 60 次而不丢失更新。
