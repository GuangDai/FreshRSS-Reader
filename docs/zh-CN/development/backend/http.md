# HTTP 抓取与 Retry-After

系统配置 `data/config.php` 的 `limits` 支持以下设置。大小以字节为单位，时间以秒为单位。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `http_max_response_bytes` | `16777216` | `httpGet()` 每个响应解压后的正文上限，默认 16 MiB；`0` 不限制 |
| `http_max_header_bytes` | `65536` | `httpGet()` 每个请求收到的全部响应头上限，包含临时响应和尾部头；`0` 不限制 |
| `retry_after_default` | `1500` | 缺失或无法解析 Retry-After 时等待的秒数；`0` 不设置新的默认等待 |
| `retry_after_max` | `172800` | 一次响应可以新增的最长等待时间；`0` 不设上限 |
| `retry_after_cleanup_limit` | `1000` | 每次清理最多处理的重试记录数量；`0` 关闭清理 |

`httpGet()` 在接收过程中检查限制，超限即失败，返回空 `body`、`fail=true`，并在 `error` 中指出对应配置名。不会把截断数据当作完整文章，也不会覆盖已有缓存。读取缓存同样限制内存读入量，超过正文上限的缓存会触发重新抓取。大页面需要提高 `http_max_response_bytes`，或明确设置为 `0`。

RSS/Atom 的 SimplePie 抓取同时设置 cURL 的 `CURLOPT_MAXFILESIZE_LARGE`，并保留调用方更严格的值。这一保护对声明长度的响应有效；未知长度响应的检查能力取决于部署的 libcurl 版本。它不等同于 `httpGet()` 的解压后正文和响应头回调限制。本地 libcurl 8.20.0 实测中，128 字节上限同时阻止了 4096 字节的普通和 gzip 响应，覆盖 Content-Length 与 chunked 两种传输；压缩数据本身仅 40 字节。该结果不替代其他 libcurl 版本的验证。SimplePie 的旧 socket 路径无法保留地址检查和 cURL 资源限制，现明确拒绝 `force_fsockopen=true`。

重定向逐跳检查目标地址，保留已有 SSRF 检查和 DNS 绑定。跨域时移除认证和 Cookie，包括系统配置中的相关 cURL 选项及 SimplePie 构造函数的初始认证头。超出重定向次数、无效目标、正文或响应头超限均返回失败；新目标的 Retry-After 也会阻止请求。SimplePie 构造函数传入的 `redirects` 参数现在在没有 cURL 覆盖时生效。

Retry-After 接受整数秒数或 HTTP 日期。短于 600 秒的默认值及短于 3600 秒的最大值现在按配置生效，不再被隐藏的最小值覆盖。现有有效等待不会被另一个并发响应缩短；降低最大值不撤销此前已经写入的等待。读操作清除 PHP 文件状态缓存，避免长时间运行的进程忽略其他进程更新的时间。

清理从请求热路径移出，供维护任务明确调用：

```php
$removed = FreshRSS_http_Util::cleanRetryAfters();
// 或指定此次最多处理的重试记录数量：
$removed = FreshRSS_http_Util::cleanRetryAfters(5000);
```

该方法逐个读取目录项，返回实际删除的过期文件数量。并发清理或写入期间拿不到锁时，本次清理返回 `0`。限制计算的是有效重试记录数量，不保证每次删除相同数量。符号链接和非普通文件会跳过；目录中这些非重试记录的遍历不占处理预算。

未到期记录在 `Retry-After/0/` 和 `Retry-After/1/` 两个目录间轮换。每次扫描过的记录移出当前目录，后续调用即使来自新进程也会继续处理剩余记录，不会总卡在相同的未到期文件前。写入的新记录进入下一轮目录，避免持续更新的热点记录挡住本轮剩余记录。原根目录的旧记录在清理时逐步迁移，读取兼容三处位置，并与写入、迁移使用同一把锁。部署升级期间不应继续运行旧版本 worker，因为旧版本不认识新的子目录。


## 缓存并发与 HTTP 状态

`httpGet()` 对同一路径的缓存刷新使用排他锁。等待中的 worker 拿到锁后再次检查缓存，成功刷新只需要一个网络请求。读取使用同一个已打开文件的大小和内容，发布使用同目录临时文件加原子重命名；读者只能看到替换前或替换后的完整内容。按年龄清理缓存时也使用同一把稳定锁，并在锁内重新检查文件时间，避免把刚替换的新正文当成旧缓存删除。无法取得稳定锁的下载不会发布缓存；已有下载结果仍可返回调用方。隐藏的锁文件不能在 worker 运行时手动删除。此并发协议覆盖 `httpGet()` 缓存；vendor SimplePie 的 `.spc` 写入目前不使用这把锁。

HTTP 304 只有在存在未超出大小限制的旧缓存时才可成功，复用旧正文并更新缓存时间。没有可用缓存的 304 返回具体错误。HTTP 500、超时及资源超限均保留旧缓存内容与时间，不会把错误正文写入缓存，也不会把旧正文伪装成成功的新响应。合法正文 `0` 可以正常命中缓存。

SimplePie 现在先接收错误响应的头部，再拒绝 HTTP 错误状态，因此会采用服务器在 429/503 中给出的 Retry-After，避免 cURL 提前终止时丢失该头部而使用默认等待时间。

## 抓取选项与缓存标识

`FreshRSS_http_Util::mergeCurlOptions()` 供 Web 抓取和 SimplePie 共用。优先顺序由低到高为系统默认值、订阅的 `curl_params`、调用方显式覆盖。正数 `timeout` 会覆盖系统的秒或毫秒超时默认值。SSL 验证设置随订阅属性应用，最终的协议限制和地址检查仍由传输层强制执行。

SimplePie 的缓存文件名根据同一组合后的选项计算。修改请求头、认证等实际抓取选项会产生相应的新缓存标识，避免文件名按一组选项计算而请求按另一组执行。直接调用 `httpGet()` 并自行指定缓存路径时，调用方仍应为不同 URL、请求参数和返回格式分配不同路径。
