# 阅读界面的屏幕与输入设备适配

独立 Reader 和 Calm 主题支持窄屏、横屏、平板、桌面、超宽屏，以及触控、键盘和从右向左的界面。适配时保留用户保存的宽度、字号和布局设置；窗口恢复到足够宽时，按保存的值显示。

## 五轮改进

| 轮次 | 发现的问题 | 改动与验证 |
| --- | --- | --- |
| 1：窄屏与短高度 | 667 × 320 视口中，侧栏约 485px 的内容被 320px 容器裁掉，底部设置入口无法到达；卡片和弹窗存在固有最小宽度 | 侧栏和必要的外层区域允许纵向滚动；弹窗随动态视口缩放；卡片最小列宽不超过可用空间；工具条和正文保留可用高度 |
| 2：自定义尺寸与触控 | 旧的 1100px 断点强制列表使用 35% 宽度，覆盖用户设置；平板上的按钮仍过小 | 按正文与列表所需的最小空间限制实际宽度；1920px 下侧栏 600px、列表 720px 可完整显示，缩窄后自动适配；触控设备按钮至少 44 × 44px，输入框字号至少 16px |
| 3：大字、长文本与双向排版 | 固定 UI 字号不跟随浏览器文字设置；长标题可能挤掉搜索框；RTL 抽屉和正文遮罩使用固定的左边定位 | UI 使用相对字号；活动订阅标题省略显示，全文仍保留在 DOM；抽屉、遮罩与选中边界按阅读方向显示；正文保留独立字号并自动判断文字方向；补齐强制颜色和减少动画的样式 |
| 4：多选与批量配置 | 订阅多选、长分类选项及批量字段在小屏上需要重新排列 | 管理移入设置页；订阅复选框与名称共享一行，按名称、分类和状态筛选；批量字段在窄屏分为两行，结果和进度可滚动 |
| 5：引擎与布局回归 | 需要确认断点两侧、极值设置和浏览器差异；经典界面的长订阅名也会撑开页面 | Chromium 与 Firefox 执行同组回归；Calm 的 320px 长名称页面由 4067px 横向溢出恢复到 320px；匿名登录基础布局由 364px 恢复到 320px；窗口调整保留列表滚动位置，也不触发新的文章列表请求 |

## 操作布局与反馈

手机正文把上一篇、已读状态、收藏和下一篇放在底部同一行，关闭按钮留在顶部。原文与图片加载在顶部直接操作，只有尚未允许显示的图片存在时才出现图片按钮；桌面在可用空间内显示动作文字。文章标题下显示来源、日期及不重复的作者信息；收藏状态同时用实心/空心星与按钮状态表达。这个安排参考 [Apple HIG Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars) 对主要操作优先级和次要操作收纳的说明。

文章列表的上一页、本页已读、下一页共用底部操作区，取消原先单独占一行的本页已读操作。订阅选择与批量编辑位于“设置 → 订阅与分类”，阅读侧栏不放管理按钮和多选工具。勾选行显示背景反馈，选择筛选结果、清除选择和批量编辑位于同一操作区。主次区分靠样式和分组，按钮保持一致的触控尺寸，参考 [Apple HIG Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)。

独立设置页在桌面使用分类侧栏，窄屏改为分类下拉选择，内容区域单独滚动。阅读器偏好、账户字段和管理工具分别显示保存与状态；批量配置仍使用内部滚动表单和固定操作区。字段获得焦点时滚入可视范围；适合并排的字段按可用空间使用两列，窄屏恢复单列。布局结合安全区域与文字放大处理，参考 [Apple HIG Layout](https://developer.apple.com/design/human-interface-guidelines/layout)。本 Web 界面选择 44 CSS px 作为触控目标，不将其与原生平台的 pt 作等价换算。

等待文章时保留关闭与切换操作，并在正文区域显示加载状态；触控环境不显示桌面键盘提示。批量进度使用实际已处理数量和目标数量，成功、失败分别报告；固定操作区保留状态、进度与停止入口。保存期间显示等待状态，避免用户猜测是否已经提交。局部反馈、稳定的位置和实际进度数值参考 [Apple HIG Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)。

Calm 配置页同时改进提交栏的对比和高度、输入框焦点边界、编辑入口的触控区域、长按钮换行及主题预览图。经典设置面板与内容预览在加载、失败、重试和关闭时也有对应反馈。

## 宽度与滚动行为

`sidebarWidth`、`listWidth`、`readingWidth` 仍是用户保存的目标宽度。三栏并排时，CSS 为列表保留至少 240px，为正文保留至少 280px 的空间，然后计算实际侧栏与列表宽度。这两个布局下限分别用 `--list-min-width` 和 `--article-min-width` 表达，集中定义在 `reader.css`。

820px 及以下使用单栏列表和可打开的侧栏抽屉。具有触控输入、宽度不超过 1100px 且高度不超过 500px 的横屏也使用该模式，避免手机横屏把正文挤成狭窄的第三栏。JS 的焦点与历史逻辑使用相同条件。打开文章后，正文覆盖列表；关闭后回到原列表。抽屉尊重侧栏设置，同时不超过视口宽度的 85%。布局变化不回写用户设置。

侧栏、文章列表、正文、设置内容与批量弹窗分别具有滚动区域。短横屏无法同时放下全部导航和操作时，外层区域也允许滚动，所有入口仍可到达。顶部工具条、正文按钮和底部操作考虑设备安全区域；页面使用动态视口高度。

正文 iframe 保持原有脚本、表单和同源访问限制。表格和代码块在自身区域横向滚动，长单词可换行，图片与图注不撑开整个正文。文章方向由正文内容自动判断；界面方向沿用 FreshRSS 的语言配置。

## 触控与辅助显示

触控设备通过 `any-pointer: coarse` 判断，包含具有触控输入的平板和笔记本。按钮至少 44 × 44px；文本输入和下拉列表至少 44px 高，字号不小于 16px。复选框保持独立选择目标，批量编辑只修改已启用的字段。

UI 字号跟随浏览器默认字号。正文的字号、行高仍由 Reader 设置决定。系统强制颜色模式保留当前项、选中项和键盘焦点的轮廓；减少动画模式禁用平滑滚动并缩短动画和过渡。

Reader 使用仓库已有 SVG 图标，列表元信息从 11px 调整为 12px，工具栏的设置入口至少 44 × 44px。抓取失败同时使用三角形和读屏文本表示。主题预览位于“外观与排版”，缓存与任务参数按设置分类显示；无效字段会定位到对应分类或展开高级区域，并聚焦该字段。[设置说明](settings.md) 列出分类、草稿和完整管理工具；[主题说明](themes.md) 列出 32 个主题、日夜切换和旧偏好的处理；[信息层级说明](interactions.md) 记录合并工具栏、即时搜索和直接批量编辑的行为。

Calm 主题同步修复配置表单、分类和订阅名称换行、侧栏滚动及矮屏提交区。基础主题的 `main.prompt` 采用受视口约束的宽度和边框盒模型，修复匿名登录页在 320px 屏幕上的横向溢出，不影响普通阅读区布局。RTL 样式由 `rtlcss` 生成，不手工维护。

## 自动化范围

`tests/browser/reader/responsive.spec.mjs` 包含 33 项用例，`tests/browser/classic/calm-responsive.spec.mjs` 包含 10 项用例，`tests/browser/auth/login-responsive.spec.mjs` 包含 4 项匿名登录用例。其中：

- Reader 尺寸覆盖 240 × 568、280 × 653、320 × 568、390 × 844、667 × 320、844 × 390、768 × 1024、820 × 1180、821 × 600、1024 × 768、1280 × 720、1920 × 1080、3840 × 2160。
- 尺寸矩阵包含侧栏 600px、列表 1000px、正文 3840px、正文 96px 字号的组合，另有最小宽度及 8px 字号用例。
- Calm 的配置、阅读设置、订阅管理、新增订阅、文章页面覆盖 5 种尺寸，共 25 个页面与视口组合。
- 200% 缩放场景使用等效的 640 × 400 CSS 视口，同时独立测试 200% UI 文字大小；不是操作系统级的真实设备缩放测试。
- 交互布局还检查正文四键不遮挡内容、批量弹窗滚动后关闭和保存仍可见、错误字段能获得可见焦点、慢网仍可关闭、分页三键不重叠，以及桌面更多菜单不被工具条裁切。独立设置页另有分类导航、订阅筛选、表单草稿和同源工具的用例，见[设置说明](settings.md#相关实现与检查)。
- 测试使用真实页面、脚本和样式。Reader 用生成的数据替代接口响应，并拦截修改请求；Calm 通过加载真实主题样式和注入测试 DOM 验证，不修改账户配置。

Chromium 和 Firefox 均完成这 47 项用例；WebKit 也已通过对应的整合回归。WebKit 的 200% 文字测试另发现并修复了 Calm 顶部设置按钮的列对齐差异，修复后页面宽度由 338px 恢复到 320px，按钮仍完整可点击。全仓浏览器检查数量记录在本目录的 README。浏览器自动化和触控模拟不等同于真实 iOS、Android 或触控笔硬件测试。

在已配置本地测试地址及独立测试账户的环境中运行：

```sh
npx playwright test --config tests/browser/config/default.config.mjs \
  reader/responsive.spec.mjs classic/calm-responsive.spec.mjs auth/login-responsive.spec.mjs --browser=chromium
npx playwright test --config tests/browser/config/default.config.mjs \
  reader/responsive.spec.mjs classic/calm-responsive.spec.mjs auth/login-responsive.spec.mjs --browser=firefox
```

测试账户通过 `FRESHRSS_TEST_USER`、`FRESHRSS_TEST_PASSWORD` 提供，服务地址通过 `FRESHRSS_TEST_URL` 设置。缺少账户变量时，Reader 和 Calm 的登录测试会跳过，不把跳过计为通过；匿名登录布局测试不需要账户变量。
